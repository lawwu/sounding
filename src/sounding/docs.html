Docs & API

One local catalog, available in the browser, terminal and agent tools.

Browse first

Catalog pages read saved metadata. No Google credentials or Google calls are needed to browse projects, datasets, table schemas and saved estimates.

Enter a project ID under Open a Google Cloud project and choose Open & import. Sounding starts importing its accessible datasets immediately, using existing credentials. Datasets appear as metadata is saved; progress stays visible while you browse.

Reload catalog rereads the local file. Refresh metadata contacts BigQuery using existing Google credentials and saves new snapshots. A whole-project refresh discovers accessible, non-hidden datasets. Select several projects or datasets to refresh together; overlapping selections are deduplicated.

Each dataset is published atomically. A failure retains its previous snapshot while other datasets finish. Datasets no longer visible in a project are retained locally. Refresh status survives browser reloads, but is held in the server's memory and disappears when that server restarts. Completed snapshots remain on disk.

Free metadata and explicit actions

Metadata refresh, previews, job history and dry runs use free BigQuery API operations. Column-cost refresh runs one dry run per top-level column; user SQL never executes. Refreshing metadata does not recalculate saved column estimates.

Schema badges mark partition columns, clustering order, declared keys and policy tags. Declared primary and foreign keys are not enforced by BigQuery. Ingestion-time partitioning uses virtual columns. Range bounds, partition expiry, labels, storage, table expiry and lineage are shown when present in the snapshot.

Models, policies and recommendations

Dataset pages list BigQuery models; open one for its type, input features, targets and remote model settings. Table pages include row-access policy names and expandable filter expressions. Membership lists are not collected. No model training, inference or policy changes run.

Project, dataset and table pages show partition/cluster recommendations and table insights. These are fetched per project/location and cached for 24 hours, including failed attempts, to conserve API quota. Last-attempt and last-success timestamps identify stale results. Suggestions are never applied. A refresh with denied or unavailable optional metadata is marked partial while successful metadata is still saved.

Existing credentials need bigquery.models.list and bigquery.models.getMetadata for models, bigquery.rowAccessPolicies.list for policies, and the BigQuery Recommender viewer permissions (such as roles/recommender.bigqueryPartitionClusterViewer) for recommendations and insights. Disabled APIs, missing permission and quota limits appear explicitly; Sounding does not enable services.

Optional row samples

Imports are metadata-only by default. Load 10 rows on a table explicitly fetches and saves a small sample using free tabledata.list. The CLI flag --include-preview-rows includes samples during harvest or refresh and prints a warning: this can add a material delay. It requires permission to read the actual data.

Samples have arbitrary order, a timestamp, and a limit of 10 rows / 256 KiB of saved JSON per native table or snapshot. This storage limit does not bound the API response size. Views and external tables are not queried. A normal metadata-only refresh does not carry samples into the new snapshot; older snapshots can still contain previously saved data.

Table query history

Choose 1–180 days (default 30), the job project and visibility, then load the top individual query jobs by billed bytes or slot time. The job project can differ from the table's project. “My jobs” is the current identity; project-wide metadata may require bigquery.jobs.listAll.

The free lookup scans at most the newest 1,000 completed top-level jobs. It matches reported table or logical-view references; scripts' children, missing references and other job projects are not included. Warnings identify truncation or unreachable locations. An empty result does not establish no usage. Metrics are whole-job totals, not a table's allocated share. SQL appears only when you choose “Show SQL & details” and is not saved.

Workload opportunity scans are separate: their default is a free preview; executing a billed scan requires explicit opt-in and a byte cap. See the CLI and MCP references.

Local files

The catalog defaults to ~/.sounding/catalog.duckdb. SOUNDING_CATALOG selects another local file. SOUNDING_JOB_PROJECT selects the default project for dry runs and job history. Live actions use Application Default Credentials already configured on this computer. This UI does not sign you in.

Command line

From the Sounding checkout, prefix commands with uv run. Run sounding --help or sounding COMMAND --help for all options.

sounding ui --open
sounding browse
sounding show orders --project my-project
sounding show id --dataset my-project.analytics
sounding describe my-project.analytics.orders
sounding dataset my-project.analytics
sounding model my-project.analytics.revenue_model
sounding recommendations my-project

Refresh with progress

# Selected datasets
sounding refresh my-project.analytics other-project.sales

# Whole projects, including newly visible datasets
sounding refresh --project my-project --project other-project

# Harvest also accepts whole projects (same discovery and progress)
sounding harvest --project my-project --project other-project

# Original dataset harvester
sounding harvest my-project.analytics
# Optional actual row data; WARNING: can add a material delay
sounding harvest my-project.analytics --include-preview-rows
sounding refresh --project my-project --include-preview-rows

Refresh and project-level harvest print the final result as JSON to stdout and progress to stderr. Partial or failed imports exit with code 2. One refresh per catalog can run at a time; reads remain available. Repeat --project to include several projects; explicitly named datasets are combined with discovered datasets without duplicates.

Inspect cost and usage

sounding column-costs my-project.analytics.orders
sounding estimate 'SELECT order_id FROM `my-project.analytics.orders`'
sounding preview my-project.analytics.orders
sounding cost-report --hours 720
sounding table-queries my-project.analytics.orders --days 30
sounding table-queries my-project.analytics.orders --project job-project --scope project --rank-by slot_ms
sounding inspect-job JOB_ID --project job-project --location US --include-sql

Workload investigations

# Free preview of the capped monitoring scan
sounding query-opportunities --location US --hours 720

# Execute only when a billed scan is intended
sounding query-opportunities --location US --hours 720 --allow-billed
sounding query-report

The scan defaults to a 100 MiB byte cap; --max-bytes-billed changes it within the supported bounds. It does not cap capacity/slot charges. Routine commands: routines [text] and routine project.dataset.routine.

Local UI API

The browser uses these same-origin endpoints. They are internal to the UI; use CLI or MCP for the supported integration interface. Every API request requires the current server's X-Sounding-Token header, supplied by the page's sounding-token meta element.

POST requests also require a same-origin Origin header and Content-Type: application/json. The server listens only on loopback, validates Host and Origin, rejects cross-site requests, and does not enable CORS.
